## 第4章 系统设计

### 4.1 系统架构设计

本系统采用**前后端分离**的架构模式，整体架构分为四层：**表现层**、**服务层**、**数据层**和**外部服务层**。这种分层架构设计实现了高内聚、低耦合的设计目标，提高了系统的可维护性和可扩展性。

#### 4.1.2 架构设计优势

1. **前后端分离**: 前端和后端独立开发、独立部署，提高了开发效率
2. **模块化设计**: 各模块相互独立，通过接口进行交互，实现了高内聚、低耦合
3. **分层架构**: 清晰的层次结构，便于维护和扩展
4. **RESTful API**: 标准化的API设计，便于第三方集成
5. **多模型支持**: 支持6个AI模型提供商，提高了系统的灵活性

#### 4.2.3 核心表结构说明

##### 1. 用户表 (auth_user)

用户表是系统的核心表，存储用户的基本信息和认证信息。主要字段包括：

- **id**: 用户ID，主键
- **username**: 用户名，唯一，必填
- **password**: 密码，加密存储
- **email**: 邮箱，可为空
- **is_active**: 是否激活
- **is_staff**: 是否为员工
- **is_superuser**: 是否为超级用户
- **date_joined**: 注册时间
- **last_login**: 最后登录时间

**表4-1 用户表 (auth_user) 结构**

| 字段名 | 类型 | 说明 | 约束 |
|-------|------|------|------|
| id | Integer | 用户ID | 主键 |
| username | VARCHAR(150) | 用户名 | 唯一，必填 |
| password | VARCHAR(128) | 密码 | 加密存储 |
| email | VARCHAR(254) | 邮箱 | 可为空 |
| first_name | VARCHAR(150) | 名 | 可为空 |
| last_name | VARCHAR(150) | 姓 | 可为空 |
| is_active | Boolean | 是否激活 | 默认 true |
| is_staff | Boolean | 是否为员工 | 默认 false |
| is_superuser | Boolean | 是否为超级用户 | 默认 false |
| date_joined | DateTime | 注册时间 | 自动设置 |
| last_login | DateTime | 最后登录时间 | 可为空 |

**关系说明**：
- 一对一 → chatbot_userprofile (用户配置)
- 一对多 → chatbot_conversation (会话)
- 一对多 → chatbot_message (消息)
- 一对多 → chatbot_passwordresettoken (密码重置令牌)
- 一对多 → chatbot_voicecallrecord (语音通话记录)

##### 2. 用户配置表 (chatbot_userprofile)

用户配置表扩展了用户信息，存储用户的个性化设置和API密钥。主要字段包括：

- **user_id**: 用户ID，外键
- **phone**: 手机号
- **avatar**: 头像
- **openai_api_key**: OpenAI API密钥
- **deepseek_api_key**: DeepSeek API密钥
- **qwen_api_key**: 通义千问API密钥
- **gemini_api_key**: Gemini API密钥
- **kimi_api_key**: Kimi API密钥
- **doubao_api_key**: 豆包API密钥
- **qwen_code_api_key**: 通义千问代码API密钥

**表4-2 用户配置表 (chatbot_userprofile) 结构**

| 字段名 | 类型 | 说明 | 约束 |
|-------|------|------|------|
| id | Integer | 配置ID | 主键 |
| user_id | Integer | 用户ID | 外键 → auth_user.id (一对一) |
